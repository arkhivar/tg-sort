# Telegram Topic Sorter

## Overview

This is a Flask application using a regular Telegram Bot API token to sort
known forum topics. It deliberately does not use a userbot, Telethon, MTProto,
API_ID, API_HASH, phone number, or personal Telegram session.

The bot learns topic IDs from incoming updates or accepts a manually imported
roster. It then validates that it is an administrator with Manage Topics and
sends a quiet marker message to each selected topic in sorted order.

## System architecture

### Backend

- Flask serves the web UI and JSON endpoints.
- A daemon thread polls Telegram with `getUpdates`.
- The poller records `message_thread_id`, topic creation metadata, and
  close/reopen state in `topics.json`.
- A queue worker performs one sort operation at a time.
- The token is read only from the `BOT_TOKEN` Replit Secret.

### Bot API methods

- `getMe` validates the token.
- `getUpdates` learns topic IDs from messages and handles `/topic`.
- `getChat` resolves group usernames and validates the target.
- `getChatMember` checks administrator and Manage Topics permission.
- `sendMessage` uses `message_thread_id` and `disable_notification`.

### Data flow

1. The user creates a bot with @BotFather and adds it as a group administrator.
2. The user sends one controlled mention/message in each existing topic.
3. The poller receives those updates and stores the observed topic IDs.
4. The user optionally imports metadata for historical topics in the web UI.
5. The user selects a group and sorting method.
6. The server validates the target group and bot permissions.
7. The worker sorts only the known/imported roster and sends quiet markers.
8. The browser polls `/status` for progress and logs.

## Telegram limitation

The current Bot API has topic methods and supports `message_thread_id`, but it
does not expose the MTProto `channels.getForumTopics` method for enumerating
historical group topics. Do not claim that a regular bot can list every old
topic. The safe fallback is update-based discovery plus manual import.

The Bot API also does not reliably expose the complete historical pinned-topic
list or historical topic titles/icons. Pinned flags in this app are therefore
explicit roster metadata, not a guessed Telegram state.

## Required configuration

### Replit Secrets

- `BOT_TOKEN`: token generated by @BotFather.
- `SESSION_SECRET`: optional Flask session secret.

No `API_ID`, `API_HASH`, `PHONE_NUMBER`, or Telethon session is required.

### Telegram permissions

The bot must be an administrator in the target forum group with **Manage
Topics**. Disable privacy mode in @BotFather if ordinary messages should be
available for discovery. Polling requires that no other process or webhook
consume the same bot updates.

## Topic roster format

The UI accepts one row per line:

```text
topic_id | title | emoji_id | pinned
123 | Announcements | 5368324170671202286 | true
456 | Support
```

Only `topic_id` is required. IDs remain strings in JSON and browser payloads,
then become integers only when sent to Telegram.

## Operational safety

- Never print or return the bot token.
- Never use a personal account to work around a missing Bot API method.
- Validate group type and Manage Topics before sending.
- Keep the topic roster limited to explicitly observed/imported IDs.
- Log API errors without credentials.
